  4. 疫情隔离管理系统

    分为pc管理端与手机移动端。

    其中管理端大致分为疾控卫健角色、转运系统角色、隔离点角色等。疾控健委角色负责对患者的信息流调、管控分配、下发转运等；转运中心角色根据接收下发的转运函生成转运单、分配司机、指定隔离点等；隔离点角色负责接收患者、分配房间、患者健康信息检测等，以及对隔离房间、楼层等信息的维护。

    移动端分为司机端、患者端以及隔离点管理端。司机端含有接收转运单、接送患者到隔离点交接等功能；患者端包含上车登记、入住登记、健康信息填报等功能；隔离点管理端负责录入患者并分配房间信息，以及后续核酸采样工作安排等功能。

    在该项目中独立负责开发隔离人员管理、患者管控信息流调、隔离登记、转运任务调度，移动端的司机接单、患者入住登记、健康信息上报等模块。

    该项目页面开发使用的技术栈主要为 React 、 Antd Hooks， 以 WS 作为前后端通信。

  5. 排班预约叫号系统

    该项目含有门诊排班、排队叫号、服务管理等模块。

    其中服务管理模块用来维护门诊排班叫号所用到的服务、以及医生科室信息等。

    排班模块则可以根据现有的班次信息、诊室、以及关联的服务等，来制定门诊班表计划，发布之后即可生成可供预约的号源。

    排队叫号则是根据已发布的号源、服务等生成不同的队列；含有分诊屏可以用来展示队列信息，以及展示医生端发出的叫号信息等；相对的医生端则是展示自己所负责的服务队列，队列中为通过预约或门诊指定的患者信息，可以对患者进行叫号操作。

    在该项目中负责对以上功能模块的维护、更新功能等。

    使用到的技术栈为 React + Antd + Redux，采用 WS 作为医生端与排队叫号pc端的即时通讯方式。

    后端方面使用到了 Ruby + Rails 的搭配。整个API采用 Restful 风格，基于测试驱动开发，实现JWT登录，使用到了中间件鉴权，采用 Docker 对项目进行容器化。
